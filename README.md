# CityRider — Logistics Management System

A production-ready monorepo for a small courier and parcel-delivery business. Built with **Turborepo + pnpm workspaces**, **Next.js 15**, **NestJS 10**, **PostgreSQL + Prisma**, and **TypeScript** throughout.

---

## Monorepo structure

```
Cityrider/
├── apps/
│   ├── web/          # Next.js 15 App Router — staff portal, rider portal, public tracking
│   └── api/          # NestJS REST API — all business logic and data access
├── packages/
│   ├── config/       # Shared ESLint, TSConfig (base / nextjs / nestjs), Prettier
│   ├── types/        # Shared TypeScript interfaces, enums and DTOs
│   ├── database/     # Prisma schema + generated client
│   ├── ui/           # Shared React component library (shadcn-style)
│   └── utils/        # Tracking number generation, Zod validators, formatters
├── turbo.json
├── pnpm-workspace.yaml
└── .env.example
```

## Getting started

### 1. Prerequisites

- Node.js ≥ 20
- pnpm ≥ 12 (`npm install -g --allow-scripts=pnpm pnpm`)
- PostgreSQL 16 running locally (or a connection string)

### 2. Environment

```bash
cp .env.example .env
# Edit DATABASE_URL and JWT_SECRET
```

### 3. Install dependencies

```bash
pnpm install
```

### 4. Database setup

```bash
pnpm db:migrate        # run migrations
pnpm db:seed           # seed default accounts (see below)
```

### 5. Run all apps in development

```bash
pnpm dev
```

| App | URL |
|---|---|
| Web | http://localhost:3000 |
| API | http://localhost:4000/api/v1 |
| Swagger | http://localhost:4000/api/docs |
| Prisma Studio | `pnpm db:studio` |

## API endpoints overview

| Resource | Base path |
|---|---|
| Auth | `POST /api/v1/auth/login`, `/refresh`, `/logout` |
| Users | `GET/POST/PATCH /api/v1/users` |
| Packages | `GET/POST /api/v1/packages`, `PATCH /:id/status` |

| Reports | `GET /api/v1/reports/packages`, `/riders`, `/financial` |

## Development notes

- All shared types live in `packages/types` — never duplicate domain types in apps.
- After editing `packages/database/prisma/schema.prisma`, run `pnpm db:generate`.
- The tracking endpoint (`/api/v1/track/:tn`) is intentionally unauthenticated — it only returns `isCustomerVisible: true` events and no internal fields.
- Financial records include an audit trail — all corrections via `/payments/:id/correct` are traced with `PaymentCorrection` records.
